# Accessibility audit (axe-core + keyboard), phase 9

Tool: `tools/e2e/a11y.mjs`, run with `tools/e2e/run-a11y.sh [out-dir]` (Playwright image,
axe-core 4.10.2 installed into /tmp/pw, not into package.json; `SKIP_BUILD=1` reuses dist).
It builds the app in local-only mode, opens each screen and state and runs axe with the tags
wcag2a, wcag2aa, wcag21a, wcag21aa and best-practice. Results are written to
`<out-dir>/a11y-results.json` (every violation with its selector, html and failure summary).
The run exits 1 if any violation is outside the canvas or if a keyboard check fails.

## Coverage (about 40 scans)

- Start screen / new-diagram dialog (before and after choosing a database), phone start screen (dark).
- Editor with a diagram, light and dark: Tables, DBML, Links, Types, Extras (Areas and Notes tabs).
- Edit card open; Diagram, Edit and View menus; the Save-as and Color-theme submenus.
- Dialogs: Open, Import (SQL), Export SQL, Export image, Preferences (settings), Create relationship,
  Empty the diagram (clear); the language menu; a visible toast.
- Open dialog and a menu in dark theme.
- German and Arabic: `lang`, `dir` (`rtl` for Arabic), no horizontal overflow, editor, menu, Open dialog.
- Phone viewport (390x844, touch): canvas and drawer.

Keyboard-only checks: Tab reaches the menubar, arrows and Enter open menus, Escape returns focus
to the menubar, Tab reaches the rail and the panel rows and their row menus; Open, Create
relationship and Clear dialogs trap focus (Tab and Shift+Tab), close with Escape and return
focus to the control that opened them; a toast lives in a live region; a visible focus
indicator (outline, ring or style change measured with computed styles, keyboard modality) on
every focusable element of five editor sections and the Open dialog.

## What was fixed

- Landmarks: the editor frame had a `<main>` inside the page's `<main id="root">`; it is now a
  `div` (`data-region="content"`), the page keeps its single main.
- Headings: a screen reader only `<h1>` with the diagram name; the side panel starts with a
  screen reader only `<h2>` ("Diagram contents"); the table editor sections are `<h3>` (was `<h4>`,
  which skipped levels in the edit card). The phone drawer keeps its own title.
- Language menu: a `DropdownMenu` that contained a search box (a `searchbox` inside `role=menu` is
  invalid) and hid the page with `aria-hidden` while it held focusable controls. It is now a
  popover with a labelled search box and a `radiogroup` of `radio` buttons. Unit test updated.
- Dialogs opened from menus or shortcuts lost focus to `<body>` on close. `useReturnFocus`
  (src/platform/ui/use-return-focus.ts) records the focused control, or the trigger of the menu
  that was open, and gives focus back on close; used by `DialogContent` and `AlertDialogContent`.
  Test: src/platform/ui/__tests__/return-focus.test.tsx.
- Import mode tabs pointed `aria-controls` at a panel that does not exist.
- Open dialog: the empty first column header is merged into the Name header (`colSpan=2`).
- DBML read-only view is keyboard scrollable (`tabIndex=0`, role textbox read-only, labelled).
- Table type pickers in the edit card now have an accessible name ("Type: integer").
- Contrast (tokens in src/globals.css, kept recognisable): dark `--muted-foreground` 66% -> 71%
  lightness (table schema labels were 4.34:1); `.dark .text-destructive` uses a lighter red
  (menu item "Delete diagram" was 3.54:1; the fill token is unchanged, so buttons keep their
  white-on-red text); the React Flow credit link is coloured with the muted token on a
  background-coloured panel (was 2.74:1 light, 1.15:1 dark). Light theme tokens needed no change.
- Toasts: Radix Toast already renders `role=status` live regions; the audit now asserts it.

## What could not be fixed here (canvas, or by design)

1. `aria-prohibited-attr` (11 nodes, one per scan with a diagram): `src/canvas/diagram-canvas.tsx`
   puts `aria-label` on a plain `<div data-testid="diagram-canvas">`. Needs a role (for example
   `role="application"` or `role="group"`) there. Not editable by this task.
2. Focus ring: canvas nodes (`div.react-flow__node`, role group) and edges (`g[role=group]`) are
   focusable but have no visible focus style. Needs a `.react-flow__node:focus-visible` outline in
   the canvas styles, and an edge focus style. The audit excludes `.react-flow` from the ring check.
3. `region` (10 nodes): the popper wrapper of an open Radix menu is portalled to `<body>`, outside
   the landmarks. Transient overlay, best-practice rule only; the audit lists it as accepted.
4. The canvas surface is not keyboard operable beyond what xyflow offers (tables are focusable,
   arrow-key movement and connecting lines are not available from the keyboard). A keyboard route to
   create a relationship exists through the Links section ("Add relationship" dialog), so the
   function is reachable, but moving tables is not.
5. Not covered by an automated check: screen reader announcement quality, reduced-motion (the
   global stylesheet already honours `prefers-reduced-motion`), zoom/reflow at 400%, and the
   share-viewer and admin pages (no diagram flow reaches them in local-only mode).
