# Fixes for rewrite/review/core-store.md

Tests live in `src/formats/sql/core-store-fixes.test.ts`,
`src/dialects/core-store-fixes.test.ts`, `src/core/core-store-fixes.test.ts`,
`src/core/wire/core-store-fixes.test.ts`, `src/store/core-store-fixes.test.ts`,
`src/formats/dbml/core-store-fixes.test.ts`, plus one case each appended to
`src/persistence/persistence.test.ts` and `src/core/history/history.test.ts`.
No existing test was edited or weakened. Describe names start with
`review core-store N`.

| # | Status | Notes and test |
|---|--------|----------------|
| 1 | fixed | Names match exactly first, then ignoring case (`src/dialects/shared/names.ts`), in ALTER, CREATE INDEX, COMMENT ON, REFERENCES, the index filter, the builder. An ALTER foreign key no longer needs the table to be found. Every unresolved ALTER, index, comment and column comment gives a warning. Tests: `review core-store 1` (3 cases). Case-sensitive duplicates are still kept apart when spelled identically (exact match wins). |
| 2 | fixed, one spec conflict | SQL Server writer and converter dedupe FK names per schema (per database for MySQL), MySQL and PostgreSQL writers dedupe too (`claimName`). Conflict: DAT-049 fixes the default link name as `<table>_<column>_fk`, so `createLink` keeps that name for the first link and only a later link with a taken name adds the holder table and column (`users_id_orders_user_id_fk`, then `_2`). Tests: `review core-store 2/9` and `review core-store 2: new link names`. |
| 3 | fixed | `openDexieStorage` clears the migration marker when the merge returned `merged`; the migration skips ids already in `designs`. QubdiDB rows are copied into QBase's legacy stores before it is deleted, so nothing is lost if the migration fails (marker stays unset, retried). Test: `review core-store 3`. Side effect: a design deleted from the new layout while its old rows survive would come back only when a late merge happens. |
| 4 | fixed | `startsConstraint` looks at the second token. `key`, `index`, `period`, `exclude`, `like`, `fulltext`, `spatial` are columns unless followed by their syntax; `like <type word>` is a column. A constraint that is read but ignored (LIKE, EXCLUDE) now warns. Test: `review core-store 4` (3 cases). |
| 5 | fixed | MySQL writer escapes `\` in COMMENT, COMMENT= and string defaults. Test: `review core-store 5`. A default that is already a quoted literal is passed through as written. |
| 6 | fixed | Converter lines `-- not created ...`, `-- Was:`, and `-- Schema:` / `-- Original schema:` / SQLite system table comments go through `oneLine`. Tests: `review core-store 6` (2 cases). |
| 7 | fixed, one spec conflict | EXP-013 sample S3 expects a bare `"status" ticket_status`. A user type is therefore written bare only when its name is plain lower case and it is in no schema or `public`; otherwise it is quoted and qualified exactly like CREATE TYPE. Test: `review core-store 7`. |
| 8 | fixed | `firstFreeName`: tables (same schema, ignoring case), columns, indexes, types, areas never reuse a name; the number still starts at count + 1 so the specified sequence is unchanged when nothing was deleted. Test: `review core-store 8` (3 cases). |
| 9 | fixed | `claimName` clips after dedupe and suffixes `_2`...: MySQL index names (64, per table), MySQL FK names (64, per database), PostgreSQL index names (60, per schema) and FK names (60, per holder table), SQLite index names (per database, no silent skip), converter indexes and FKs. Tests in `review core-store 2/9` (7 cases). |
| 10 | fixed | `exportSql` filters with the design's own default schema. Test: `review core-store 10`. |
| 11 | not fixed | Performance only (bulk delete is quadratic); not trivial, left as is. |
| 12 | fixed | `item.update` on a link adds any field normalised by many/many to the inverse patch. Test: `review core-store 12`. |
| 13 | fixed | `box` is validated on update and on insert (finite numbers, positive size). Entity `width` is clamped to 224..450 in `entity.update`. Limitation: undo of a change away from an imported width outside that range restores the clamped value. Planner `createRegion`/`createMemo` turn a non-finite position into 0 and a bad size into the default, because the canvas drop test (`src/canvas/drop-items.test.tsx`) passes no coordinates and produced a NaN box. Test: `review core-store 13`. |
| 14 | fixed | `END IF/LOOP/WHILE/REPEAT` no longer lower the block depth; `END CASE` closes once. No `DELIMITER` handling (not requested). A T-SQL script that writes `END` directly followed by an `IF` statement without a semicolon or GO now keeps the block open until the next `GO`. Test: `review core-store 14` (2 cases). |
| 15 | fixed | Warnings for a duplicate column, a table defined twice, an index with unresolved members (the whole index is dropped), an unqualified name matching several schemas; unqualified FK targets prefer the holder's schema; `CREATE TABLE users` after `public.users` is kept. Tests: `review core-store 15` (5 cases). `ALTER ... ADD COLUMN` duplicates are still skipped without a warning. |
| 16 | mostly fixed | `__proto__`, `constructor`, `prototype` ids are replaced by new ids with a warning (the old id still resolves references); link resolution is keyed by the first table with a raw id (the duplicate gives the existing "used twice" warning); the column `type` keeps extra keys (`TypeRef.extra`, written back); `serialise` cuts unknown values nested deeper than 100 levels. Not fixed: dependencies are still not checked against existing tables. Tests: `review core-store 16` (4 cases). |
| 17 | fixed except the unmount error | Autosave has `maxWaitMs` (default 10 s). Adapters record `wasRemoved(id)` and autosave skips a removed design (an explicit `save` clears it). `selectVisibleEntities` is memoised. The unmount flush already reports through `onError`/`onSaveError`; unchanged. Tests: `review core-store 17` (3 cases). |
| 18 | partly fixed | Fixed: `CREATE PROCEDURE` is a last-resort SQL Server signal (`detect`); wire edits skip `undefined` for required fields; an undo or redo step that fails with `not-found`/`invalid` is dropped from its stack (store applies the returned history); DBML `prepare` ignores braces in strings, backticks, `'''` notes and `//` comments. Tests: `review core-store 18` (3 cases and one history case). Not fixed: DBML index types `gin/fulltext/spatial` (an existing test, `dbml.test.ts`, requires `type: gin` on export, so the export stays; the import parser's btree/hash limit is the parser's); raw CHECK/default text (by design); `merge-previous` numeric id collision (rare). |
